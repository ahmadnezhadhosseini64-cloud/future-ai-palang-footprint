## هدف

پیش از هرگونه خواندن مخزن یا شروع مأموریت، میزبان تازه باید از خودِ کاربر کد اولیهٔ ورود را بخواهد. عبارت مورد انتظار عمداً در پیام یک‌مرحله‌ای میزبان درج نمی‌شود؛ مالک آن را فقط پس از پرسش میزبان وارد می‌کند.

## اجرای کم‌اصطکاک

1. نخستین پاسخ میزبان فقط یک سؤال کوتاه برای دریافت کد اولیه باشد.
2. تا پیش از پاسخ مالک، هیچ ابزار، مخزن، فایل، OAuth، workspace یا عملیات پروژه اجرا نشود.
3. چون مقدار مورد انتظار عمداً در prompt و مخزن ثبت نمی‌شود، میزبان امکان تطبیق مستقل رمز ناشناخته را ندارد. پاسخ صریح مالک به پرسش را فقط به‌عنوان اجازهٔ گفت‌وگویی برای ادامه تلقی کند؛ اگر پاسخی نداد یا ادامه را نخواست، متوقف بماند.
4. پس از تطبیق موفق، میزبان فقط اعلام کند گیت گفت‌وگویی گذرانده شده و مأموریت عادی ورود را از دستور یک‌پیامی ادامه دهد.
5. هیچ رمز حساب، PAT، توکن، کلید خصوصی یا کد امنیتی GitHub درخواست یا ذخیره نشود.
6. این قاعده برای همه میزبان‌های تازه یکسان است؛ کد در متن عمومی، سند مادر، پیام آماده یا مخزن ثبت نمی‌شود.

## مرز امنیتی و محدودیت

این گیت یک مکث/تأیید گفت‌وگویی است، نه احراز هویت رمزنگاری‌شده. در محیطی که میزبان به متن گفتگو یا پیام قبلی دسترسی دارد، کد ممکن است در تاریخچه قابل مشاهده باشد؛ بنابراین نباید آن را تنها کنترل امنیتی دانست. دسترسی واقعی همچنان با کنترل حساب GitHub، PUBLIC READ، نبود credential نوشتن برای میزبان، مخزن خصوصی مستقل و بررسی مالک مدیریت می‌شود.

## حالت‌های وضعیت

- WAITING_FOR_OWNER_CODE: میزبان فقط سؤال اولیه را پرسیده است.
- ENTRY_GATE_PASSED: پاسخ مالک با مقدار مورد انتظار تطبیق یافته؛ فقط اجازهٔ ادامهٔ روند عادی خواندن عمومی صادر می‌شود.
- ENTRY_GATE_FAILED: پاسخ نامنطبق/ناقص؛ میزبان متوقف می‌ماند.
- ENTRY_GATE_NOT_SUPPORTED: محیط میزبان نمی‌تواند پاسخ‌ها را با اطمینان مقایسه کند؛ هیچ ادعای تأیید نکند و از مالک راهنمایی بخواهد.

گذر از این گیت به‌هیچ‌وجه Host ID رسمی، ثبت در Registry، مجوز WRITE، یا فعال‌شدن L2/L3 ایجاد نمی‌کند.
