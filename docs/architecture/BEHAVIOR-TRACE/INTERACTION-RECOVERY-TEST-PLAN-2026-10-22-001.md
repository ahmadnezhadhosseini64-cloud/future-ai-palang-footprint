# آزمون بازیابی تعامل پس از شروع مجدد

- Stable ID: PALANG-INTERACTION-COLD-START-RECOVERY-TEST-2026-10-22-001
- Version: 1.0.0
- Status: OPEN / TEST PLAN
- Governing event: EVT-0085

## هدف
ثابت شود که پس از شروع مجدد می‌توان با داشتن یک IN-... یا OUT-... به زوج تعامل و سپس تمام رویدادهای مرتبط، نسخه‌های معماری، شواهد، شکاف‌ها و مسیر بازیابی رسید.

## مراحل آزمون
1. یک رکورد واقعی و مجاز در دفتر ثبت و شناسه‌های زوج آن یادداشت شود.
2. رکورد با JSON Schema اعتبارسنجی شود؛ نسخهٔ ابزار و خروجی واقعی اعتبارسنجی ثبت شود.
3. محیط/جلسهٔ آزمایش بسته و از نو آغاز شود.
4. فقط با شناسهٔ ورودی، رکورد و زنجیرهٔ lineage بازیابی شود.
5. آزمایش از نو تکرار شود، این بار فقط با شناسهٔ خروجی.
6. تطبیق شود که هر دو مسیر به یک interaction_id، ورودی، خروجی و مجموعهٔ مرتبط رویدادها/معماری/شواهد/شکاف‌ها می‌رسند.
7. نتیجه با شواهد، زمان UTC، زمان معادل تهران، نسخهٔ آزمون و هر شکست ثبت شود.

## معیار قبولی
- هر دو شناسه به همان زوج برسند.
- پیوندها کامل و بدون شناسهٔ مرده باشند.
- رکورد طرح‌واره را بگذراند.
- پس از شروع مجدد، داده به حافظهٔ زندهٔ جلسه وابسته نباشد و از منبع ثبت‌شده بازیابی شود.
- هر اختلاف یا نقص به‌عنوان GAP ثبت شود، نه اینکه پنهان یا خودکار اصلاح شود.

## وضعیت فعلی
NOT RUN — این سند طرح آزمون است، نه اثبات اجرای موفق. این مکالمه به‌تنهایی آزمون سردِ شروع مجددِ یک runtime مستقل را اثبات نمی‌کند.
