## 1. ورودی و تصمیم حاکمیتی
درخواست کاربر: مدل‌ها و الگوهای ورودی/خروجی به معماری اولیه افزوده شوند؛ معماری اولیه تغییر نکند و فقط رشد کند؛ سند مرجع مادر ساخته و به‌صورت رویداد ثبت شود؛ رفتارشناسی و آینده‌نگری معماری ادامه یابد.

**تصمیم حاکمیتی:** معماری اولیه immutable baseline (خط مبنای تغییرناپذیر) است. توسعه فقط به شکل افزوده‌های نسخه‌دار، فایل‌های تکمیلی، رویدادهای جدید، پیوندها، آزمون‌ها و نسخه‌های جدید مدل انجام می‌شود. متن تاریخی معماری اولیه نباید بی‌صدا بازنویسی یا حذف شود. اگر اصلاح لازم شد، اصلاح به‌صورت amendment (الحاقیهٔ روشن) با علت، شاهد و نسخه ثبت می‌شود؛ نسخهٔ قبلی حفظ می‌ماند.

## 2. رفتارشناسی این چرخه
- مشاهدهٔ ورودی: کاربر صریحاً بین «رشد» و «تغییر معماری اولیه» تمایز گذاشت.
- تفسیر معماری: نیاز به حفاظت از خط مبنا، امکان تکامل بدون از دست دادن منشأ، و پیوند بین رفتار واقعی تعامل و طرح آینده.
- رفتار مورد انتظار سامانه: افزودن پیوندها و لایه‌های توسعه، ثبت تصمیم‌ها، حفظ نسخه‌ها، آزمون بازخوانی و گزارش مستقل وضعیت هر مقصد.
- ریسک‌های ممنوع: بازنویسی بی‌صدا، ادعای فعال‌سازی خودکار بدون پیاده‌سازی، ساخت زمان یا شاهد، یا تعمیم موفقیت مخزن به مقصدهای دیگر.

## 3. دامنهٔ ثبت
1. قاعدهٔ «معماری اولیه تغییر نمی‌کند؛ فقط رشد می‌کند» به‌عنوان قاعدهٔ حاکمیتی ثبت شود.
2. مدل FIOBAM و قرارداد زوجی INT/IN/OUT به معماری اولیه از طریق یک بخش الحاقی پیوند بخورد.
3. سند مرجع مادر و لنگر مستقل ساخته و از شاخص‌ها قابل بازیابی شوند.
4. رویداد و سند مرجع پس از نوشتن دوباره خوانده و تطبیق داده شوند.
5. مسیر آینده‌نگر، شکاف‌ها و آزمون‌های هنوز اجرا‌نشده صریح باقی بمانند.

## 4. خط لولهٔ رشد کنترل‌شده
CAPTURE → CLASSIFY → PAIR → PROVENANCE → MODEL → APPEND-ONLY CHANGE → VERSION → TEST → WRITE → READ-BACK → MATCH → VERIFY → LINK → RESUME → LEARN

ترجمه: دریافت → دسته‌بندی → زوج‌سازی → ثبت منشأ → مدل‌سازی → تغییر افزایشی → نسخه‌بندی → آزمون → نوشتن → بازخوانی → تطبیق → راستی‌آزمایی → پیونددهی → ادامه → یادگیری.
