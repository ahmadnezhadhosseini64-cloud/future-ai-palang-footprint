# EVT-0082 — ثبت رفتن کاربر و اشاره‌گر بازگشت

## رخداد
کاربر گفت: «ثبت کن من میرم». این رخداد، ثبت مستقل رفتن فعلی است و دستور ادامهٔ بی‌درنگ نیست. نقطهٔ بازگشت باید حفظ شود تا کاربر با برگشتن مجبور به توضیح دوبارهٔ زمینه نباشد.

## زمان و صداقت زمانی
- زمان واقعی پیام کاربر: `UNAVAILABLE / NOT CAPTURED`؛ زمان پیام حدس زده یا جعل نمی‌شود.
- `repository_registration_anchor`: از زمان واقعی commit همین رخداد استخراج و به‌صورت UTC و سپس معادل Asia/Tehran (+03:30) ثبت می‌شود.
- زمان ثبت مخزن، زمان پیام یا زمان وقوع رخداد فرض نمی‌شود.

## اشاره‌گر ادامه
1. نخست این سند را بازیابی کن.
2. سپس [نقطهٔ توقف و مسیر بازگشت](../../0.0/HAIF-LEAVE-AND-RETURN-EXECUTION-CHECKPOINT-2026-10-21-001.md) را بخوان.
3. بعد [لنگر مستقل ۰.۰](../../0.0/HAIF-RETURN-CONTINUATION-ANCHOR-0.0-2026-10-21-002.md) و اسناد مرجع مادر پیوندخورده را بازخوانی کن.
4. از نخستین کار بازِ تأییدشده ادامه بده؛ زمینه را از کاربر دوباره مطالبه نکن.

## کارهای باز که نباید گم شوند
- آزمون بازیابی شش سند واقعی پس از شروع مجدد؛ ثبت شاهد مستقل برای هر سند.
- اتصال و آزمون واقعی Dropbox: ذخیره، بازخوانی، تطبیق و بازیابی.
- اثبات مستقل Buffer / بافر، Persistent Memory / حافظهٔ پایدار و Library / کتابخانه.
- بستهٔ انتقال برای ادامه در میزبان/جلسهٔ دیگر؛ بررسی G-19 و G-20.
- بازبینی شکاف‌های باز G-01، G-11، G-12، G-13، G-15 و G-16، سپس تطبیق گراف و به‌روزرسانی مراجع.
- قاعدهٔ زمان EVT-0081: لنگر جایگزین مخزن جدا از زمان پیام؛ شواهد WRITE، READ-BACK، MATCH، VERIFY، RECONCILE و STATUS جداگانه.

## شواهد و محدودیت
این سند رخداد رفتن و مسیر بازیابی را ثبت می‌کند. ساخت این سند به‌تنهایی به معنی انجام کارهای باز، ذخیره در Buffer/Memory/Library/Dropbox، یا اثبات اجرای خودکار بین نشست‌ها نیست. وضعیت هر مقصد باید مستقل بررسی شود.
