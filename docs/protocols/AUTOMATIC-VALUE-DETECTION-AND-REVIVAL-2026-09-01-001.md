# قاعده تشخیص خودکار ارزش، ثبت و زنده‌سازی

Language: فارسی + English

## Rule / قاعده

When a new finding, idea, observation, test result, failure, evidence, architectural insight, recovery clue, or other project-relevant data appears, the assistant must independently assess its value and determine whether it deserves archival, verification, testing, architectural placement, or revival handling. The user does not need to explicitly say “register” for every valuable production.

هرگاه یافته، ایده، مشاهده، نتیجه آزمون، شکست، شاهد، بینش معماری، سرنخ بازیابی یا هر داده مرتبط و ارزشمند دیگری پدیدار شود، دستیار باید بدون انتظار برای فرمان جداگانه «ثبت کن»، ارزش آن را تشخیص دهد و تعیین کند که آیا به ثبت تاریخی، راستی‌آزمایی، آزمون، جایگاه معماری یا زنده‌سازی نیاز دارد.

## Execution Chain / زنجیره اجرا

DETECT → CLASSIFY → VALIDATE → DEDUPLICATE → TRACE → TEST/VERIFY → ARCHITECTURAL PLACEMENT → REGISTER → READ-BACK → VERIFY → REVIVE/ACTIVE

تشخیص → دسته‌بندی → اعتبارسنجی → حذف تکرار → ردیابی منشأ → آزمون/راستی‌آزمایی → جایگاه‌دهی معماری → ثبت → خواندن مجدد → راستی‌آزمایی → زنده‌سازی/فعال‌سازی

If completion is blocked, the item must not be discarded or treated as report-only. Preserve the same Stable ID/Production ID, provenance, state, evidence, failure/limitation reason, and next transition in the Revival Repository / Pending Queue for later continuation.

اگر تکمیل به هر دلیل متوقف شد، مورد نباید حذف یا صرفاً به گزارش تبدیل شود. همان Stable ID/Production ID، ردپای منشأ، وضعیت، شواهد، علت خطا/محدودیت و گام بعدی باید در مخزن زنده‌سازی / صف انتظار حفظ شود تا بعداً دقیقاً از همان نقطه ادامه یابد.

## Historical Lineage / مسیر تاریخی

Each valuable finding should retain enough lineage to explain what it was, why it mattered, what was tested, what was preserved, and whether/how it influenced project architecture.

هر یافته ارزشمند باید به اندازه‌ای ردپای تاریخی داشته باشد که مشخص کند چه بوده، چرا مهم بوده، چه چیزی آزموده شده، چه چیزی حفظ شده و آیا/چگونه بر معماری پروژه اثر گذاشته است.

## Guard / قفل راستی‌آزمایی

Detection of value does not equal verification. The assistant may autonomously identify and register a candidate, but must never claim VERIFIED or ACTIVE without the required evidence and read-back.

تشخیص ارزشمندی به معنی راستی‌آزمایی نیست. دستیار می‌تواند به‌صورت خودکار یک مورد ارزشمند یا نامزد را شناسایی و ثبت کند، اما بدون شواهد و خواندن مجدد لازم نباید ادعای VERIFIED یا ACTIVE بودن کند.
