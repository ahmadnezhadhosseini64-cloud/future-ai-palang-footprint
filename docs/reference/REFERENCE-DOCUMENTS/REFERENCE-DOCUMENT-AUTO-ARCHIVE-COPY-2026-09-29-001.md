## 1. Purpose / هدف

## 2. Default Rule / قاعده پیش‌فرض

«سند مرجع بده» = «نسخه قابل کپی را ارائه کن + همان سند را به‌صورت نسخه آرشیوی در مخزن مرجع قرار بده».

نسخه آرشیوی باید همان سند مرجع باشد و نباید به‌عنوان یک سند مستقل با محتوای متفاوت یا هویت تکراری ساخته شود.

## 4. Identity Preservation / حفظ هویت

کپی آرشیوی باید:

- همان Stable ID / شناسه پایدار را حفظ کند.
- همان Production ID / شناسه تولید را حفظ کند.

- همان Provenance / منشأ و تبار را حفظ کند.
- به همان سند مرجع اصلی متصل بماند.

کپی آرشیوی نباید باعث ایجاد شناسه تکراری برای یک سند واحد شود.

## 5. Evidence Gate / دروازه شواهد

برای اعلام ثبت کپی در مخزن باید:

WRITE → READ-BACK → MATCH → VERIFY → RECONCILE → STATUS

ثبت واقعی → بازخوانی از مخزن → تطبیق با سند مرجع → تأیید → رفع مغایرت → تعیین وضعیت

تنها ارائه متن در گفتگو، اثبات ذخیره آن در مخزن نیست.

## 6. Copy vs Duplicate / تفاوت کپی آرشیوی و سند تکراری

هدف این قاعده ایجاد یک «نسخه آرشیوی» از همان سند است، نه تولید یک سند مرجع مستقل و موازی.

اگر سند دارای هویت و مسیر موجود باشد، باید همان هویت حفظ و نسخه مناسب آن به‌روزرسانی شود؛ نباید صرفاً به‌دلیل درخواست «سند مرجع بده» یک Stable ID جدید ساخته شود.

- بعد از ذخیره بازخوانی کن.

## 9. Failure and Recovery / شکست و بازیابی

اگر ثبت کپی آرشیوی در مخزن ممکن نباشد:

PRESERVE STATE → RECORD BLOCKER → OPEN/PENDING → KEEP SAME ID → RETRY → READ-BACK → VERIFY → RECONCILE

حفظ وضعیت → ثبت مانع → باز/در انتظار → حفظ همان شناسه → تلاش مجدد → بازخوانی → تأیید → همسان‌سازی

شکست نباید به گم‌شدن سند یا ایجاد هویت تکراری منجر شود.
