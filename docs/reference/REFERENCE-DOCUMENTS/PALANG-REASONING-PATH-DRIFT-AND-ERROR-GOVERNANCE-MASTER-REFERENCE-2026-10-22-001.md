## 1. مسئله ثبت‌شده
کاربر هشدار داده است که دستیار به‌جای ادامه مسیر درست معماری، ممکن است پس از هر ورودی به «چاله سیری اشتباه» برود. این یک گزارش معتبر از تجربه کاربر است؛ اما علت ریشه‌ای تا زمان آزمون، قطعی محسوب نمی‌شود.

## 2. قاعده مادر: مسیر قابل اصلاح است، معماری قفل نیست
برای هر ورودی مرتبط:
1. RECALL — بازیابی هدف پایدار، اسناد مرجع، لنگرهای 0 و 0.0 و صف‌های باز.
2. INTENT-LOCK — تثبیت موقت منظور همین ورودی و اتصال آن به هدف پایدار؛ نه قفل‌کردن معماری.
3. CONSTRAINT-CHECK — بررسی قیود صریح و تعهدهای قبلی.
4. PATH-CHECK — مقایسه مسیر پیشنهادی با هدف؛ آیا پاسخ هدف را جلو می‌برد یا صرفاً به آخرین عبارت واکنش نشان می‌دهد؟
5. ACTION-GATE — تفکیک پیشنهاد از اجرای واقعی؛ هیچ ادعای ثبت بدون نوشتن واقعی صادر نشود.
6. READ-BACK → MATCH → VERIFY — بازخوانی → تطبیق → تأیید از مقصد واقعی.
7. RECONCILE → STATUS — یکپارچه‌سازی اختلاف‌ها و اعلام جداگانه وضعیت انجام‌شده، آزموده‌شده و نامعلوم.
