## Fundamental rule
Any unverified, incomplete, conflicting or untested item remains OPEN and LIVING across every checkpoint until explicit acceptance criteria are met and evidence is independently read back. No state is promoted by assertion, repetition, or file presence alone.

## Additive lifecycle
Preserve → classify → provenance → stable/production ID + version → register → write → read back → match → validate → reconcile → integrate → status. A failure remains part of the history and receives a correction link; it is never silently erased.

## Host transfer rule
The exported package must reconstruct mission, canonical state, parent/child lineage, evidence, versions, failures, open gates and next deterministic action from files alone. Host capabilities are separately observed and tested. Persistence and idle/background execution remain NOT VERIFIED until a real runtime test proves them.
