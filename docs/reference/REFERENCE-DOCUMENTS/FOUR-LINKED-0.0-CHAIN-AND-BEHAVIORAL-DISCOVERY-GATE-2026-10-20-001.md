## 4. دروازهٔ کشف رفتاری پیش از ارتقا به معماری
هر ورودی/خروجی می‌تواند حاوی یک الگوی رفتاری یا کشف جدید باشد. حفظ رویداد الزامی است؛ اما ورود آن به معماری مادر خودکار نیست. چرخه:
CAPTURE → CLASSIFY → COMPARE → EVIDENCE → HYPOTHESIS → TEST → RECONCILE → PROMOTE OR KEEP IN QUEUE.
معنی: ثبت → طبقه‌بندی → مقایسه با الگوهای قبلی → جمع‌آوری شاهد → فرضیه‌سازی → آزمون → تطبیق → ارتقا یا نگهداری در صف.

معیارهای دروازه:
1. مشخص شود مشاهده از مسیر انسان، رفتار پاسخ‌دهی AI، رفتار ابزار، محدودیت میزبان یا اثر محیطی آمده است.
2. الگو با رفتارها/رویدادهای قبلی مقایسه و موارد تکراری حذف یا به هم پیوند داده شوند؛ تاریخچه پاک نشود.
3. بین مشاهده، تفسیر و فرضیه تفکیک شود؛ حدس به‌عنوان واقعیت ثبت نشود.
4. شواهد، موارد نقض، شرایط تکرار و سطح اطمینان ثبت شوند.
5. اگر الگو قابل آزمون است، آزمون کوچک و نتیجه ثبت شود. آزمون ناموفق هم شاهد است و باید حفظ شود.
6. دسته‌بندی پروژه تعیین شود: Noise / نویز؛ Local Bug / خطای محلی؛ Host Limitation / محدودیت میزبان؛ Architectural GAP / شکاف معماری؛ Valuable Idea / ایدهٔ ارزشمند؛ Fundamental Discovery / کشف بنیادی.
7. فقط پس از شواهد کافی و تطبیق با Master–Child–Rahm، پیشنهاد ارتقا به هستهٔ مادر مطرح شود. موارد ناکافی در صف OPEN / PENDING می‌مانند.
8. ثبت یک رویداد یا رفتار در دفتر، معادل تأیید عمومی یا تبدیل آن به قانون معماری نیست.
