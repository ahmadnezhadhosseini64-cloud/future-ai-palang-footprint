## قاعدهٔ انتشار هر تکمیل بعدی
1. تغییرات را فقط در منبع اصلی بسته اعمال کن.
2. تست‌های واحد، schema، بسته‌بندی و بازیابی را روی همان revision اجرا کن.
3. ZIP را با همان نام canonical از نو بساز؛ ZIP جداگانهٔ نسخه‌دار منتشر نکن.
4. artifact را دریافت/بازخوانی کن؛ فهرست اعضا، اندازه، SHA-256 و تست‌ها را ثبت کن.
5. در manifest داخلی نسخهٔ منطقی را افزایش بده، ولی Stable ID و نام سازگار آرشیو را حفظ کن.
6. هش نسخهٔ پیشین را به‌عنوان سابقه نگه دار و هرگز به bytes جدید نسبت نده.
7. بعد از هر build، گیت میزبان مستقل را جداگانه اجرا کن. CI موفق به‌تنهایی پذیرش میزبان را اثبات نمی‌کند.
