## تصمیم تثبیت‌شده
هر تعامل واقعی که از یک میزبانِ ثبت‌شده و از مسیر مجاز دریافت می‌شود، باید به‌صورت یک جفت مستقل IN/OUT یا رویداد صریحِ ناقص/ناموفق ثبت شود؛ هر رکورد دارای شناسه یکتا، میزبان و نشست، منشأ، والد/نقطه قبلی، نسخه مرجع، زمان‌های قابل‌اثبات، digest، طبقه‌بندی حریم خصوصی، وضعیت اعتبارسنجی و رسید بازخوانی باشد. رکوردها append-only هستند؛ اصلاح با رویداد اصلاحی جدید انجام می‌شود، نه بازنویسی خاموش تاریخچه.

## مرز اختیار
ثبت دائمی به معنی پذیرش محتوای ورودی در MASTER نیست. هر ورودی میزبان نامطمئن و ابتدا QUARANTINED است. فقط پس از پالایش، تطبیق، آزمون RAHM، نامزد CHILD و تأیید صریح مالک، بخش پذیرفته‌شده می‌تواند به سند مادر ارتقا یابد. میزبان حق نوشتن مستقیم به MASTER یا main را ندارد.

## قاعدهٔ تداوم
- رویدادهای واقعیِ دریافت‌شده از مسیر مجاز باید durable commit و read-back شوند.
- اگر آداپتر/مجوز/اتصال موجود نیست، وضعیت NOT CAPTURED / NOT CONNECTED ثبت می‌شود؛ نباید وانمود کرد گفتگو ذخیره شده است.
- هر شکست ثبت، رویداد شکاف مستقل با وضعیت WRITE_FAILED / READBACK_FAILED می‌سازد و برای reconciliation باز می‌ماند.
- داده خام مکالمه پیش‌فرض ذخیره یا ارسال نمی‌شود؛ حداقل داده مجاز و پالایش‌شده نگه داشته می‌شود.
- UNKNOWN برای زمان/منشأ غیرقابل‌اثبات مجاز است؛ زمان حدسی ممنوع است.
- مالک، اختیار لغو میزبان، محدودسازی دسترسی و تصمیم نهایی ارتقا را حفظ می‌کند.
