## روش رسیدگی
1. تثبیت snapshot، commit، نسخهٔ اسکریپت و artifact خام هر گزارش.
2. استخراج اعضای هر گروه برخورد، بدون حذف یا بازنویسی.
3. برای هر عضو بررسی: Stable ID، Production ID، Reference ID، Event ID، مسیر، hash محتوا، تاریخچهٔ commit، نقش سند، نسخه، والد/فرزند، و پیوندهای ورودی/خروجی.
4. طبقه‌بندی نتیجهٔ هر گروه: LEGITIMATE REUSE / DUPLICATE / COLLISION / STALE INDEX / NEEDS OWNER DECISION.
5. ادغام یا تغییر شناسه فقط با حفظ lineage و پیوند جانشینی؛ حذف تاریخی ممنوع مگر با تأیید صریح مالک و طرح بازگشت.
6. EVT-0089: پیدا کردن گزارش خام، رشتهٔ زمانی دقیق، قالب، زمینه، timestamp منبع، مقدار UTC/تهران موجود و دلیل شکست parser؛ سپس بازتولید محاسبه و بررسی منبع مستقل. تا آن زمان مقدار اصلی را حفظ و برچسب NEEDS REVIEW نگه دار.
7. اجرای ممیزی تازه پس از اصلاح، بازخوانی گزارش، تطبیق شمارش‌های قبل/بعد، و ثبت شواهد.
