مالک خواست معماری چندمیزبانی HAIF برای ورود سادهٔ میزبان‌های تازه عملیاتی شود: هر میزبان هویت مستقل و فضای کاری جداگانه داشته باشد؛ فقط در محدودهٔ همان فضا فعالیت کند؛ به مخزن مرکزی، سند مادر، Registry، تنظیمات یا فضای میزبان دیگر حق نوشتن/تغییر نداشته باشد؛ و خروجی‌هایش برای مالک قابل بررسی، استخراج و بازیابی باشد.

دامنهٔ این ورودی فقط آماده‌سازی و اجرای نخستین ورود یک میزبان با یک پیام است. میزبان باید ابتدا مرجع عمومی را بدون OAuth بخواند، هویت و قابلیت‌های واقعی را گزارش کند، workspace خصوصی را فقط در صورت پشتیبانی واقعی محیط بسازد و فعالیت آغازین را در همان workspace انجام دهد. شناسهٔ رسمی پس از رسید و تأیید مالک تخصیص می‌یابد. هیچ دسترسی نوشتن به مخزن مرکزی داده نمی‌شود.
