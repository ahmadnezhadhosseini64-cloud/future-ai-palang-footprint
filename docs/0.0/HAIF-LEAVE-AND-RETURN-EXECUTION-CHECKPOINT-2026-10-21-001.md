## 3. دو قاعدهٔ لازم‌الاجرا
### A — لنگر زمانی جایگزین
اگر زمان واقعی پیام در دسترس نیست، آن را جعل نکن. فیلد زمان پیام ناموجود بماند و زمان واقعی commit همان رکورد در مخزن به‌عنوان `repository_registration_anchor` ثبت شود. ابتدا UTC، سپس معادل دقیق Asia/Tehran (+03:30). زمان commit زمان پیام یا زمان وقوع رویداد محسوب نمی‌شود.

### B — شواهد جداگانهٔ هر مرحله
برای هر مرحله شواهد مستقل ثبت کن: WRITE (نوشتن)، READ-BACK (بازخوانی)، MATCH (تطبیق)، VERIFY (راستی‌آزمایی)، RECONCILE (تطبیق با معماری) و STATUS (وضعیت). زمان ثبت نهایی زنجیره نیز جداگانه ثبت شود و جای شواهد مراحل را نگیرد.

## 4. ترتیب ادامه پس از بازگشت
1. بازخوانی همین سند، لنگر اصلی ۰.۰، سند مرجع مسیر بازگشت و EVT-0081 از مخزن.
2. بررسی وضعیت واقعی آخرین commitها و گردش‌کارها؛ ثبت نتیجهٔ هر اجرا با commit و زمان خودش؛ عدم تکرار آزمون موفق مگر با تغییر یا دلیل روشن.
3. ادامهٔ آزمون بازیابی شش سند واقعی پس از شروع مجدد؛ تطبیق شناسه، مسیر، نسخه، تبار و هش/محتوا برای تک‌تک شش سند.
4. ادامهٔ Dropbox: اتصال واقعی، ذخیرهٔ فایل آزمون، بازخوانی همان فایل، تطبیق محتوا/هش و بازیابی پس از شروع مجدد.
5. اثبات مستقل Buffer (بافر)، Persistent Memory (حافظهٔ پایدار) و Library (کتابخانه). هیچ موفقیت مخزن را به مقصدهای دیگر تعمیم نده.
6. ساخت و آزمون بستهٔ انتقال برای ادامه روی میزبان/جلسهٔ دیگر؛ بررسی G-19 و G-20.
7. بازبینی شکاف‌های معماری باز G-01، G-11، G-12، G-13، G-15، G-16؛ رفع تعارض‌های معنایی، تبار و پیوندها؛ به‌روزرسانی نمایه و سند مرجع مادر با شواهد.
8. در هر مرحله، اگر ابزار یا دسترسی وجود نداشت، آن را BLOCKED / اثبات‌نشده ثبت کن؛ ادعای اجرا یا ذخیره‌سازی نکن.

## 5. چرخهٔ اثبات
`PRESERVE → IDENTIFY → REPOSITORY TIME ANCHOR → WRITE → READ-BACK → MATCH → VERIFY → RECONCILE → STATUS`

حفظ → شناسایی → لنگر ثبت مخزن → نوشتن → بازخوانی → تطبیق → راستی‌آزمایی → تطبیق معماری → اعلام وضعیت.

## 6. وضعیت مقصدها در این نقطه
- Repository / مخزن GitHub: برای اسناد و قواعدی که پیوند داده شده‌اند، ثبت قبلی تأیید شده؛ این سند تازه باید پس از ساخت بازخوانی شود.
- Buffer / بافر: ثبت/بازخوانی مستقل در این عملیات اثبات نشده.
- Persistent Memory / حافظهٔ پایدار: ثبت/بازخوانی مستقل در این عملیات اثبات نشده.
- Library / کتابخانه: ثبت/بازخوانی مستقل در این عملیات اثبات نشده.
- Dropbox: اتصال و آزمون ذخیره/بازیابی همچنان باز است.
- آزمون شش سند: باز تا زمان وجود شواهد موردبه‌مورد برای هر شش سند.

## 7. ثبت زمان
- زمان واقعی پیام کاربر: `UNAVAILABLE / NOT CAPTURED` مگر اینکه فرادادهٔ معتبر دیگری یافت شود.
- زمان ثبت مخزن: پس از ایجاد، از فرادادهٔ واقعی commit استخراج می‌شود؛ UTC اول و تهران دوم.
- زمان بازخوانی و زمان commitهای بعدی فقط در صورت وجود شاهد واقعی ثبت می‌شوند؛ از حدس یا زمان فعلی تقریبی استفاده نشود.
