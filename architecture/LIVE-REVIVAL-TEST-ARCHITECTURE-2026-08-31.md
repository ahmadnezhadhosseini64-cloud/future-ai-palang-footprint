Define the live test architecture for proving that a historical project artifact can be retrieved, understood, revived, inherited by the current architecture, registered, evidenced, read back, and retrieved again.

Can the current architecture turn one genuinely historical artifact into a durable, traceable, re-retrievable living project artifact without inventing or overwriting its historical lineage?

## Pass Conditions
- Historical source is actually retrieved.
- Artifact identity and lineage remain intact.
- No duplicate current artifact is created when an equivalent capability already exists.
- Current 0.0/master governance is inherited.
- A new registration/provenance record identifies the revival event.
- Repository read-back matches the written revival record.
- A second retrieval finds the revived record by stable path/identifier.
- Evidence is sufficient for the claims made.

## Boundary
A repository PASS proves durable repository registration and re-retrieval. It does not by itself prove independent runtime/playground execution.

## Failure Handling
Any failed stage becomes a Failure → Learning candidate. The failed claim is not promoted to VERIFIED until the missing evidence is supplied.
