# SEARCH / RECOVERY ARCHITECTURE INDEX

Reference: 0.0
Status: ACTIVE / LIVING / PERMANENT

## Canonical Method
ARSM-2026-08-31-001 — Archive Revival Search Method

## Architectural Role
ARSM is the default discovery/search pattern for historical recovery, archive excavation, command discovery, rule discovery, production discovery, checkpoint recovery, failure mining, concept discovery, and lineage reconstruction.

## Default Pattern
ONE DIG → MULTI-LENS EXTRACTION

Every standard excavation pass should, in one coordinated pass, apply the relevant ID, Command, Rule, Failure, Concept, and Lineage lenses; then feed all candidates into the common validation/revival pipeline.

## Mandatory Pipeline
RETRIEVE → CLASSIFY → CROSS-LINK → DEDUPLICATE → VALIDATE → REVIVE/ABSORB → INHERIT → REGISTER → APPLY/TEST → EVIDENCE → READ-BACK → VERIFY → RECONCILE → REPORT

## Inheritance
ARSM inherits the 0.0 / Master governance and is itself inherited by future archive/recovery search operations. It does not override higher-level governance and does not convert discovery into verification.

## State Separation
FOUND ≠ VALIDATED ≠ REVIVED ≠ VERIFIED.

## Coverage
A pass may be called complete only after all applicable lenses have been attempted and cross-linked. Unresolved items remain UNKNOWN/PENDING or Candidate Path / Recovery Pending.

## Reuse Points
Apply ARSM to:
- repository/archive searches
- memory/retrieval investigations
- command and rule recovery
- production and checkpoint archaeology
- provenance/evidence reconstruction
- failure-to-principle discovery
- architecture lineage recovery
- playground/runtime candidate discovery

## Evidence Boundary
Only actual execution, evidence, read-back, and verification can establish execution status. Repository persistence must not be confused with runtime execution.
