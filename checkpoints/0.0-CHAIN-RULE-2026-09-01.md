## Rule

From the 0.0 reference onward, project continuation is represented as an explicit connected chain, not as isolated outputs.

Every substantive continuation node MUST preserve:

`Previous Node → Current Node → Next Node`

and MUST carry:
- Production/Connection ID
- Date
- Exact local time
- IANA timezone + UTC offset
- Previous verified node
- Current action/output
- Next intended action
- Evidence/verification state
- Explicit unverified gaps

## Chain

`0.0 → ADP-2026-08-31-001 → ADP-2026-09-01-001 → CCP-2026-09-01-001 → NEXT-ADP-OBSERVATION`

The chain is cumulative: a new step inherits the valid lineage of the prior node and must append its own timestamped node rather than creating an unconnected narrative step.

## Hammered finding

The prior continuation behavior was incomplete because it identified the next step but did not consistently expose the full previous/current/next connection at the point of output. This rule closes that presentation/execution gap at the project-protocol level.

## Evidence boundary

This registration verifies the rule's canonical repository registration and read-back. It does not by itself prove independent automated runtime execution across separate playgrounds.
